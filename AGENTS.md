# Word Cottage

Це основний локальний проєкт користувачки для вивчення англійської. Спілкуйся українською. Продовжуй роботу з наявними файлами; опис поточного стану міститься в `PROJECT.md`, інструкція запуску — у `README.md`.

Ці правила діють для всього репозиторію. Нові прямі вказівки користувачки мають пріоритет над зафіксованими тут вимогами.

- Репозиторій: https://github.com/olgaonufrak/word-cottage
- Опублікований сайт: https://olgaonufrak.github.io/word-cottage/
- Основна гілка: `main`. Працюй із кореня репозиторію, а не з батьківської папки чи старого архіву.

## Файли та робота

- Статичний сайт у `dist/`: HTML, CSS і звичайний JavaScript, без npm та серверного застосунку. `Start.cmd` відкриває локальну копію.
- Спочатку перевір поточні файли та Git-стан. Зберігай зміни інших чатів і користувачки. Не перезаписуй проєкт старою копією чи архівом.
- Перед редагуванням переглянь `git status --short`, поточну гілку, `git remote -v` і потрібні файли. Перед commit ще раз переглянь diff; додавай лише файли своєї задачі. Не видаляй чужі зміни через reset або checkout. Якщо зміни іншого чату безпосередньо конфліктують із твоїми, спочатку узгодь їх із користувачкою.
- Основні файли: `dist/app.js` — навчання та навігація; `dist/search.js` — пошук, особисті слова та словникові дані; `dist/data.js`, `dist/stage1-data.js`, `dist/stage2-data.js`, `dist/stage3-data.js` — словники; `dist/style.css` — оформлення.
- Зберігай порядок підключення скриптів у `dist/index.html`: `data.js`, `stage1-data.js`, `stage2-data.js`, `stage3-data.js`, `search.js`, `app.js`. Особисті слова мають відновлюватися перед прогресом навчання.
- Підключення `app.js` має параметр версії `v`. Після змін `app.js` оновлюй цей параметр у `dist/index.html`, щоб браузер завантажував актуальне навчання після публікації.
- Шляхи до ресурсів повинні працювати з підкаталогу `/word-cottage/` на GitHub Pages та в локальній копії. Використовуй відносні шляхи для наявних ресурсів. Не додавай збірку, фреймворк або сервер без потреби в поточній задачі.
- Ідентифікатори слів уже використовуються для прогресу в localStorage. Зберігай наявні ID при зміні порядку карток або оформлення.
- Додані користувачкою слова та прогрес зберігаються в браузері. Папка містить код і навчальні словники, але не копію її браузерного прогресу.
- Ключі збереження: `word-cottage-learned` і `word-cottage-personal-words`. Не очищуй їх і не змінюй формат без збереження наявних даних. Між пристроями та адресами сайту автоматичної синхронізації немає.

## Узгоджена поведінка

- На вході рівно дві групи: «Слова на кожен день» та «Основа для початківця».
- У першій групі чотири етапи; Етапи 1, 2 та 3 заповнені. Етап 3 містить 25 розділів у порядку користувацького списку, по 30 карток — разом 750. Етап 4 залишається порожнім, доки користувачка не попросить його заповнити.
- Назви тематичних розділів англійські; український підпис під ними — дрібним шрифтом та малими літерами.
- Вибір розділу відкриває повний список слів і перекладів. У ньому є позначки вибору та англійське аудіо, яке не змінює позначки. Унизу кнопка «Почати вчити».
- Далі кількість із кнопками −/+, варіанти 5/10/20, потім свайпи. Якщо слова позначені в списку, подальший набір обмежений ними. Без позначок доступний увесь розділ.
- Свайп вправо — вчити, вліво — пропустити. Навчання починається лише після набору обраної кількості. Вертикальний жест по картці не прокручує сторінку.
- Пошук знаходить слова з усіх словників та підтримує онлайн-пошук. Компактний результат із перекладом, транскрипцією й аудіо обох мов. Не повертай довгі визначення без запиту користувачки.
- Зберігай «Вивчені слова», повторення, навчання у двох напрямках і поточне оливкове оформлення.
- Підбір голосів використовує браузерні API та доступні словникові записи. Не описуй це як пряме підключення до Google Перекладача. Зміни аудіо й свайпів перевіряй також у браузері, коли він доступний; мобільне звучання залежить від пристрою.

## Перевірка й оновлення

- Для змін навчання використовуй відповідні перевірки з `checks/` через Node.js. Вони перевіряють логіку з імітованим DOM, а не реальний браузер чи звучання голосів. `checks/README.md` описує команди.
- Словники Етапів 1, 2 і 3: `node checks/verify-stage-one.cjs`, `node checks/verify-stage-two.cjs` та `node checks/verify-stage-three.cjs`. Список і ручний вибір: `node checks/verify-section-list.cjs`. Свайпи й кількість: `node checks/verify-swipe-selection.cjs`. Голоси: `node checks/verify-natural-voice.cjs`.
- Запускай перевірки, що стосуються зміни, та `git diff --check`. Для змін лише документації достатньо перевірити текст, посилання й diff. Не повідомляй про виконані перевірки, яких фактично не запускав.
- Після зміни функцій або словників актуалізуй `PROJECT.md` і `README.md`.
- Користувачка обрала GitHub для збереження коду та GitHub Pages для публікації. Використовуй Git і GitHub, не використовуй Sites/ChatGPT hosting для подальших деплоїв. Не створюй нових архівів як основний спосіб збереження.
- Локальна папка залишається основою. Після авторизованих змін зроби commit і push у наявний GitHub-репозиторій, указаний в `origin`; не створюй інший репозиторій для кожного чату.
- Зберігай історію Git. Не використовуй force push і не включай у commit локальні інструменти, тимчасові файли чи браузерний прогрес. Якщо push відхилено через нові зміни на GitHub, отримай їх і узгодь зі своєю роботою, не перезаписуючи чужі коміти.
- `.github/workflows/pages.yml` перевіряє навчання та автоматично публікує тільки `dist/` після push у `main`. Публікація має завершитися успішно в GitHub Actions перед повідомленням про оновлений сайт. Pull request запускає перевірки без публікації.
- Не зберігай токени та облікові дані в документах, скриптах або архівах.
- У відповіді стисло поясни результат, виконані перевірки та статус push або публікації. Давай посилання на змінені файли й сайт, коли це допомагає користувачці.
